# AGENTS.md

This file provides guidance and architecture rules when working with code in this repository.

Street Football Chaos: a 3v3 top-down arcade football game in plain browser JavaScript (canvas, procedural pixel art, WebAudio). It ships as a web build (itch.io) and an Electron desktop build (Steam). The README (in Vietnamese) documents gameplay rules and tuning knobs in detail. Some of it is out of date: its online section predates the dedicated server, and its Core/team counts are old.

## Commands

| Task | Command |
|---|---|
| Serve the game (http://localhost:8080) | `npm run serve` (`-- --port N`) |
| Game + local dedicated match server (ws://localhost:8081, URL injected at serve time) | `npm run online` |
| Desktop build in dev (Electron; Steam P2P if Steam is running, App ID 480 from `steam_appid.txt`) | `npm start` |
| Deploy the server image to every Render service (only when asked) | `npm run server:deploy` (`-- --dry` lists services) |
| Match server tests (server + client, no browser) | `npm run server:test` |
| Single test file | `node server/test/room-test.js`, `client-test.js`, `hardening-test.js`, `reconnect-test.js`, `queue-test.js`, `compression-test.js`, `story-test.js` or `invite-test.js` |
| Translation check (missing keys, `{var}` / tag mismatches; exits 1 on errors) | `node scripts/i18n-check.js` |
| Rebuild the Japanese subset font after editing `src/i18n/ja.js` | `python scripts/build-ja-font.py` |
| Steam build (`dist/steam`; Steam page not live yet, so this build is behind) | `npm run build:steam` |
| itch.io web / desktop builds (DEMO) | `npm run build:itch-web` / `npm run build:itch-desktop` |
| CrazyGames web build (DEMO) | `npm run build:crazygames` |

There is no bundler, linter or unit-test framework for the game itself. Gameplay is checked in the running game:
- `sandbox.html` is the VFX/Core playground.
- `index.html?ulttest` (or `?ulttest=moon_stomp`, or SETTINGS › TEST › ULT TEST ROOM) is the dev-only Ultimate test room (`src/ui/ulttest.js`): 3v3 training, X refills, `[` `]` switch Ultimate, `\` awakened form (X4), `O` enemy Ultimates, `F` frozen dummies. Stripped from packaged builds.
- `index.html?storytest` (or SETTINGS › TEST › STORY TEST) is the dev-only FOOTBALL STORY test page (`src/ui/storytest.js`): pick any Story + round, then MATCH / BEFORE + MATCH / AFTER SCENES / INTRO / OUTRO / WHOLE STORY. `?storytest=market_cup.2` kicks off that round directly. In a test match: `7` pitch rule fires now, `8` / `9` +1 goal for you / them, `0` win now, `-` replay the round. Results save like a real match. Stripped from packaged builds.
- `SFC.app.game` in the console gives live access to the match, e.g. `SFC.app.game.cores.add(0, 'thunder_kick')`.
- `SFC.Profile.data` holds the save; call `SFC.Profile.save()` after editing it.
- `index.html?lang=es` forces a language; `?lang=pseudo` turns on pseudo-localization.

Opening `index.html` from disk mostly works, but browsers block the XHR that loads `assets/sfx/*.wav` over `file://`, so recorded SFX fall back to synthesized sound. Use `npm run serve` when sound matters.

## Architecture

**No modules.** Every file is a classic `<script>`, and **load order matters**. Each file is an IIFE that attaches to the global `window.SFC` namespace (`SFC.Game`, `SFC.Session`, ...). Tuning data lives in `window.SFC_CONFIG.*`, defined by `config/*.config.js`. All balance numbers belong in `config/`, not in code.

**Script list = `scripts/manifest.js`, the single source.** It lists every file in load order, and each file names the targets that load it:
- `game` = `index.html`
- `sandbox` = `sandbox.html`
- `itch` = `tools/itch-page/generate.html`
- `server` = the match server, loaded directly by `server/sim.js`; simulation code only

To add, remove or reorder a script, edit `FILES` there and run `npm run manifest`. That rewrites the `<!-- scripts:begin -->…<!-- scripts:end -->` block in each HTML page; never edit that block by hand.
- `npm run serve` / `npm run online` regenerate stale pages on start.
- Every `npm run build:*` fails via `node scripts/manifest.js --check` if the pages are out of date.

**Folders under `src/`.**
- `engine/`: utils, input, gamepad, audio, storage, i18n.
- `meta/`: profile, mainpath, teammates, settings, social (progression and save data).
- `entities/`, `systems/`, `game/`: the simulation.
- `render/`, `ui/`: drawing and screens.
  - The in-match DOM UI is one object, `SFC.UI`, split by screen: `ui/matchui.js` is the core (`init`, `show`, pause, `consume` = match events → UI, mouse), and `hud.js` (HUD, skill bar, banners/toasts), `draft.js` (Core draft), `endscreen.js` (results) and `endtest.js` (dev, `SFC_DEBUG`) each add methods to it. Shared HTML helpers are in `ui/helpers.js` (`SFC.UIHelpers`). Out-of-match screens are `ui/menu.js`.
- `net/`: online play.

"Core" always means the **Core Upgrade** gameplay feature (`cores.config.js`, `systems/cores*.js`), never a folder.

**Runtime.**
- `src/main.js` owns `SFC.app`: screens (`menu | game | pause | intro | story`), modes (`single | online`), and a fixed 60 Hz step driven by `requestAnimationFrame`. A Web Worker clock keeps online matches ticking in hidden tabs.
- `SFC.Game` (`src/game/match.js`) is one match: a kickoff → play → goal → draft → end state machine, configured entirely by an `opts` object. Examples: `humanTeam: -1` for an AI-only demo, `seats` for online slots, `solo`, `training`, `mainPath`, `tutorial`. The header comment documents every option.
- The simulation is `src/entities/` + `src/systems/`:
  - `actions`: kicks, passes, attacks
  - `ai`, `human`: the controllers
  - `cores` / `cores-new` / `cores-hybrid` / `cores-ult2`: `CoreSystem`, plus per-Core `Behaviors` objects hooked by id (`onShoot`, `onPass`, ...). `cores-ult2.js` holds the 2026-10-15 redesigned Ultimates (`docs/ULT_REDESIGN.md`); their pitch objects (walls, pillars, mirrors, anvils...) are cosmetic `Effects.prop` + collision in `sys.task`
  - `effects`: VFX state; `vfxkit.js` extends `SFC.Effects.prototype`
- `src/render/` and `src/ui/` only read game state. The simulation has no DOM dependencies, which is what lets it run headless on the server.

**Meta / persistence.**
- `SFC.Profile` (level, gold, inventory, attributes), `SFC.MainPath` (career ladder: Areas are Elo ranges; ranked 3v3 against real players when the server can match some, empty seats / unmatched players get bot-driven fake players from `matchmake()`; a `pending` loss is saved at kickoff so quitting mid-match still counts), `SFC.Mates` (AI teammates) and `SFC.Social` (placeholder friend list / chat / username friend requests / 3-player party with bot-driven fake friends, key `sfc_social_v1`) are all saved through `SFC.Storage`.
- `SFC.Achievements` (`src/meta/achievements.js`, list in `config/achievements.config.js`, page `src/ui/achievements.js`, opened from the TROPHY ROOM) computes progress straight from the profile (stats, Elo, unlocked Cores…). The profile only stores claimed ids (`Profile.data.ach`). Rewards go straight in: a costume to the inventory, or a free gacha box to the SHOP.
- **TROPHY ROOM** (`src/ui/trophies.js`, `SFC.TrophyUI`, page `trophy`, behind the trophy button under SETTINGS on the home screen) is where players look back on what they achieved: a pixel room (canvas drawn with the cut-scene helpers through `SFC.Story.paint`) with one glass case per Story holding that Story's own trophy once won (`stories.list[].trophy`: pot · owl · bowl · cup, drawn by `SFC.StoryCup.trophy`), a detail panel (first win date `story.<id>.first`, best final score `fin`, stars, champion costume), a records wall (peak Elo, best Area, career stats, ULT BOOK) and the ACHIEVEMENTS button (Esc there returns to the room).
- **FOOTBALL STORY** (`docs/FOOTBALL_STORY.md`; being replaced as the main mode by **GOAT PATH**, see below; its page `story` is now only reachable from the TROPHY ROOM): co-op PvE knockout cups, the 2nd tab of the PLAY screen (`RANKED · FOOTBALL STORY · PRIVATE MATCH`). One Story = 4 matches (Round of 16 → Final), lose = out, every Story the same rules; what differs is **how the story is told** (user rule 2026-10-20; a per-Story play format was tried and rejected): `stories.list[].tell` picks a presentation in `src/ui/story.js` `TELL` that wraps the cut-scene templates (`diary` summer diary · `manga` panels + balloons · `tv` live cooking show · `film` sepia flashback reel), with chapter cards from `stages`; Cores reset every match, a draw goes to an unlimited golden goal (`opts.knockout`). Content is config only (`config/stories.config.js`: rounds, opponent teams, AI Elo, signature Core, dialogue, 3 challenge stars, champion costume with `noBox`). Logic `src/meta/cup.js` (`SFC.Cup`: in-memory run + bracket sim, saved progress in `Profile.data.story`, rewards via `Profile.awardMatch`), UI `src/ui/cup.js` (`SFC.CupUI`, pages `story` and `cup`), match built by `app.startCupMatch`. The story is told with PROLOGUE-style cut scenes (`SFC.Story.play(scenes, done, null, { speaker, music })`): each dialogue line in config becomes one scene drawn by a reusable template in `src/ui/story-cup.js` (`Story.addArt`: cupAlley, cupHost, cupFace, cupTalk, cupSad, cupRival, cupLift, cupMemory (sepia flashback), cupVoice, cupItem; backgrounds follow the Story's `theme`: alley · rooftop · market · stadium, trophy `pot` · `owl` · `bowl` · `cup`). 4 Stories ship (Ward Cup, Rooftop Night League, Night Market Cup, Grandpa's Legends), difficulty rising by `tier`. Each Story has its own plot concept and narrator (`narrator` in config; user rule: no plot template shared between Stories, concept table in `docs/FOOTBALL_STORY.md`). Each opponent can have a **pitch rule** (`rounds[i].mod`, tuning in `stories.mods`; user rule: heavy-handed is fine, but never take away or ban Cores): `src/systems/matchmods.js` (`SFC.MatchMods`, sim side; hooks in `match.js`, `human.js`, `actions.js` lightHit, `player.js` hit, `g.aiHook`) + `src/render/modsdraw.js` (props); plus in-match opponent barks (`rounds[i].barks`, popup kind `talk`) and a starting score (`rounds[i].score`). All 16 opponents have one (table in `docs/FOOTBALL_STORY.md`). Each Story stays self-contained (no cross-Story plot). No Elo; matches count toward the normal stats. Demo builds play `demo.stories` Stories. Solo (1 human + 2 AI mates; the mates play at the round's AI Elo and copy the opponent team's stats, `stories.mateStats` / `Cup.mateSpec`) or **online co-op** (PLAY WITH FRIENDS / JOIN on the Story tab): a player-hosted `Room` with `story` (never on the dedicated server), everyone on team 0 bringing their own character, empty positions = the host's AI mates. The host owns the real `Cup.run` and sends `Cup.share()` in `lobby` packets (`k` story id, `c` cup state); guests keep `Cup.mirror()`. Pre-match scenes play together (`cs` / `csd`, host waits up to `net.sceneWait`). Guest mirror games set `opts.mirror` so `MatchMods` only keeps the rule for drawing. Each machine pays its own rewards (`Cup.pay`), team stars come from the host (`ts`). Page `slobby` in `src/ui/cup.js`; test `server/test/story-test.js`. On Steam, rooms (Story `slobby` and the PRIVATE MATCH lobby) also show INVITE FRIENDS (`Session.canInvite` / `invite()` → Steam overlay invite dialog; the overlay is enabled in `electron/main.js`); an accepted invite (callback `GameLobbyJoinRequested`, whose lobby id arrives as an exact bigint, or launch arg `+connect_lobby <id>`) becomes the UI-free Session event `invite {code}`, and `OnlineUI.tryInvite` joins once the player is free in the menus (leaving any current room first). Test `server/test/invite-test.js`.
- **GOAT PATH** (`docs/RUN_DESIGN.md`): the main mode being built, a 3-act Slay-the-Spire-style run, 2nd tab of PLAY (`RANKED · GOAT PATH · PRIVATE MATCH`; the Ranked Area map page `road` is now called AREA MAP). Phase 1 is in: config `config/run.config.js` (map generation, node types, acts with opponent pools and bosses, Elo per act/floor), logic `src/meta/run.js` (`SFC.Run`: seeded map per act with no team met twice on one path, run state saved in `Profile.data.run` after every node, stats `Profile.data.runs`, `pending` at kickoff so quitting mid-match forfeits via `Run.settle()` at boot), UI `src/ui/runmap.js` (`SFC.RunUI`, page `run` = PLAY tab, `runmap` = map + act card + run-over screen), match built by `app.startRunMatch` (`opts.run`, knockout, opponent pitch rule / barks / signature looked up from `stories.list[].rounds` by team via `Run.opp`). Lose any match = run over; FORFEIT on the tab, the map and the pause menu. Cores still reset every match. Phases 2–5 are in too: **BADGE** run items (`run.badges`, only the player's character; stats via `Run.avatarStats`, school badges through `opts.coreBoost` / `draftBias`, `opts.ultGain`, `opts.score`), run cash, pick-1-of-3 rewards, Shop, Locker Room (heal / upgrade), injuries, **Skill games** (`src/systems/drills.js`, `opts.drill`: a real match with its own clock / win rule, hooked into `match.js`; not counted as a match), **???** events (`run.mystery`, `run.events`), act cut-scenes reusing the old Stories' narrators and telling styles, meta gold at run end, and the **Core Road now unlocks from run progress** (`run.coreRoad`, `Profile.data.runs.road`; Ranked no longer unlocks Cores). PLAY opens GOAT PATH (first tab); demo builds play act 1 only (`demo.runActs`). Still to do: co-op runs, a run-based TROPHY ROOM.
- **Goal celebrations** are a costume slot (`cel` in `progression.items`, 20 moves, `look.cel`) sold only in the Celebration Box (box `kind: 'cel'`; costume boxes never drop them). After a goal (not an own goal) the scorer performs it for `match.goalCelebration` seconds and teammates jog over, while the camera zooms in on them (`Renderer.goalCam`, `game.celebration.camera`; render-only, so online guests get it from the synced goal state). AI / fake players pick one by rarity (`game.celebration.botWeights`) and keep it all match. Simulation (pick + movement) is `src/systems/celebrate.js` (the server runs it too); poses, props and particles are `src/render/celebrate-draw.js`, all stateless functions of time so menu previews and online guests draw the same thing. Online, the move rides on the `goal` event (`pid`, `cel`), so no snapshot field and no protocol bump. A server that hasn't been redeployed strips `look.cel` (`sanitizeLook`), so real players there get the default move.
- `SFC.Storage` writes to `localStorage` on the web and to JSON files with `.bak` copies on desktop (via `electron/preload.js`). See `docs/SAVE.md`.

**Online** (`src/net/`). The model is host-authoritative, and the same room logic runs in two places:
- `room.js` (`SFC.Room`) holds the UI-free room rules: lobby slots, owner, starting a match, the tick loop, snapshot broadcast. It runs in the browser when a player hosts (Steam P2P via `transport-steam.js`, or PeerJS/WebRTC via `transport-peer.js`) and in Node on the dedicated server (`server/`, reached through `transport-server.js`).
- `session.js` (`SFC.Session`) is the player's online session and has **no UI**. It never calls `Menu`, `UI`, `Audio`, `Intro` or `Input`, and contains no player-facing text. It reports everything through events (`Session.on('busy' | 'waiting' | 'lobby' | 'notice' | 'role' | 'start' | 'toLobby' | 'player' | 'owner' | 'reconnecting' | 'getReady' | 'closed', fn)`) with neutral reason codes. It gets game data through `Session.provide({ profile, area })`. Guests send input bitmasks and draw a **mirror `Game` that is never simulated**.
- `src/ui/online.js` (`SFC.OnlineUI`) is the online UI. It turns those events into pages, messages, banners and sounds, owns all online texts (`TEXT`, `REASONS`), and routes in-match input (pause overlay, draft, result screen, intro). `main.js` calls `OnlineUI.tick/view`, while menus call `Session`'s commands (`createRoom`, `joinRoom`, `cancel`, `leave`, `startMatch`, `requestSlot`, `updateProfile`, `prepare`…) and read its state. To change how online looks, edit the UI files only; `client-test.js` fails if `src/net/` references the UI.
- **Where players find it:** the PLAY screen has two tabs, switched with Q/E (LB/RB) in the style of Rocket League.
  - **RANKED** is menu page `party`: Main Path matchmaking. Its header (Area + progress bar) opens **GOAT PATH** (page `road`, `src/ui/road.js`): a horizontal sea map where each Area is an island (its arena thumbnail, name flag, entry Ultimate / Cores). The ⅓ / ⅔ Core Road milestones are waypoints on the path, and the player's character stands at their current Elo. Everything is shown (`mainPath.roadSpoilers: true`; `false` hides unreached Areas as `???`).
  - **PRIVATE MATCH** covers pages `online`, `join` and `lobby`: room codes, versus or co-op vs bots, no Elo. It's drawn by `Menu.renderPrivate` in the same `pt-*` layout. OnlineUI still navigates with `Menu.go('online' | 'join' | 'lobby')`.
- `isHost` means this machine runs the match. `isOwner` means this player controls START / BACK TO LOBBY. Use `isOwner` for UI gating.
- **Several servers** (`net.server.urls`, one per region; `net.server.url` overrides with a single server, which is what `npm run online` and the tests set). The client pings every server's `/healthz` (`NetServer.probe`, CORS-readable; asleep / wrong protocol / draining = skipped this time, full = skipped for create and search) and uses the lowest ping. CREATE ROOM tries servers in ping order, JOIN tries each awake server until one has the room (codes don't say which server), and a reconnect goes back to the server holding the room (`NetServer.home`). Ranked search queues on the lowest-ping server; while alone it checks the others every `hopEvery` s and moves to one with players waiting (`healthz.queue`; of two lone players, only the one on the later server in `urls` moves, so they don't swap); a `solo` from its server moves it to another server with someone waiting, else AI; `searchMax` caps the whole search. If no server answers the ping (all asleep, or an old server without CORS), everything behaves like one server: wait for the first one to wake. All of this is invisible to players. The ping readout ends with a short alias of where the match runs (`Session.serverAlias`): a server's `alias` from its `urls` entry `{ url, alias }` (`RS` = Render Singapore, `RO` = Render Oregon), `PP` for player-hosted PeerJS rooms, `PS` for Steam P2P. Every room has one, so it doesn't single out any model.
- CREATE ROOM tries the server first when a server URL is set, then falls back to player-hosting. PRIVATE MATCH › CONNECTION (`AUTO` / `DIRECT`, saved as `Settings.roomDirect`, only shown when a server URL is set) lets the player skip the server and host directly (`Session.createRoom({ direct })`); its wording stays neutral. All room codes are 7 characters; JOIN recognises a server room by its first character (`net.server.codeFirst`, see `NetCommon.isServerCode`). Steam codes always start A–D, and PeerJS codes avoid those characters.
- **Players must never be able to tell which model a room uses.** Every message, error text (`ERRORS` in `transport.js`), room code and lobby tag (HOST = room owner) is identical across server, Steam and PeerJS. Don't mention servers, hosting machines, P2P, Steam, PeerJS or waking in player-facing text; `client-test.js` fails if any appears.
- `sync.js` defines what guests see:
  - `snapshot()` / `apply()` copy the player fields named in `PF`.
  - `capture()` wraps a **hard-coded list of `Effects` method names** and replays them on guests.
  - A new player field that rendering needs, or a new effect method guests should see, must be added there. Otherwise it silently won't appear online.
- **Ranked matchmaking** (PLAY › START with no party). `Session.queue()` sends `queue{elo,role,pf}` to the server, where `src/net/matchmaker.js` (`net.queue`, server-only) groups 2–4 players by a widening Elo window. A `Room` with `ranked` lineup then plays the match with no lobby or owner, and AI fills the empty seats. The client gets `start{opts.ranked, opts.mainPath}` and records its own Elo.
  - Every failure emits `solo`, and the menu runs the offline `MainPath.matchmake()`.
  - **Players must not be able to tell real players from AI** (the user's decision). Both look the same in MATCH FOUND, the intro (Elo badges), the pause menu (it doesn't freeze ranked matches, offline included), the draft timer and the result screen. Only your own control ring shows, and there are no away/left banners. One accepted exception (the user's call): online ranked matches show the ping readout (`src/ui/online.js`, bottom-left) and per-player match pings on the result screen, offline ones have none. Those result-screen pings: each client sends its median match ping (`mp{ms}`, every `net.pingShare` s and at the final whistle, `NetStats.matchPing`), the Room broadcasts `pg{p:{playerId: ms}}`, and in ranked matches the AI fill-ins get believable pings (real players' median × a fixed random factor, `Room.botLag`) so the scoreboard never shows who is real. Old servers / clients ignore `mp` / `pg`, so no protocol bump.
  - UI code tells ranked apart with `game.opts.mainPath` (`UI.ranked`), and online rooms with `UI.roomMatch`.
- Reconnect lives in `Room` too: a mid-match disconnect marks the member `away` for `net.reconnectGrace` seconds (AI plays the seat). `hello{tok}` reclaims it via `rejoin()`, and whoever runs the Room must call `room.expire(Date.now())` periodically. Never send a `lobby` packet mid-match: guests treat it as "match over, back to lobby"; resume data travels inside `start{opts.resume, opts.lobby}`.
- Bump `net.protocol` when the message format changes. The server must be redeployed together with the client.
- **Versions.**
  - Server: `server/package.json` `version` is `<net.protocol>.<minor>.<patch>` (semver, e.g. `5.1.0`), and it's also the Docker image tag. The server refuses to start if the major doesn't equal `net.protocol`, so a protocol bump means the server goes to `<new protocol>.0.0` (or `.1.0`).
  - Client: the game's semver is `version` in the root `package.json`. The full client version is `<version>-<net.protocol>` (e.g. `1.1.0-5`; `NetCommon.clientVersion()`), shown on the SETTINGS heading. Dev runs show `dev-<protocol>`, because `config/build.config.js` has `SFC_VERSION_STRING = 'dev'` and `scripts/strip-debug.js` writes the real number when packaging.
  - The handshake carries both (`cv` from the client, `sv` in `room` / `err` replies), and the server logs which client version opened or joined each room. `/healthz` reports `version`.
- **Live server deployment only happens on request.** The match server runs on Render as several web services named `sfc-server*` (one per region, e.g. `sfc-server`, `sfc-server-sg`; listed in `net.server.urls`), all from the Docker Hub image `team41sfc/sfc-server:<tag>`.
  - `npm run server:image` builds and smoke-tests the image locally (tag = server version). That's all Claude does by default.
  - Pushing (`npm run server:image -- --push`) only happens when the user asks for it in chat; pushes to the hub are limited.
  - Deploying (`npm run server:deploy`, `-- --dry` to list, `-- --only <name,...>`) points every `sfc-server*` service at the tag through the Render API, waits for each deploy, and checks `/healthz` reports the version. Services whose latest deploy is already live on that tag are skipped unless `--force` (a re-pushed tag can carry a new image; the workflow forces after pushing). Also only when the user asks. The API key comes only from the `RENDER_API_KEY` environment variable; never print it or write it to a file in the repo. The same steps run from GitHub as the manually triggered **Server deploy** workflow (`.github/workflows/server-deploy.yml`: tests, push, deploy; secrets `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`, `RENDER_API_KEY`). Until a deploy, the live servers keep the old protocol, so a client with a newer `net.protocol` falls back to player-hosting / AI ranked.
- `server/README.md` covers server env vars, Docker (`docker build -f server/Dockerfile .`, built from the repo root) and the handshake.

**Build flavors** (`config/build.config.js`):
- `SFC_DEBUG`: dev-only features (test menus, cheats). `scripts/strip-debug.js` runs as electron-builder `afterPack` and inside `build-web.js`, and uses Terser to delete `if (SFC_DEBUG)` branches. The build **fails** if dev-only marker strings (the `MARKERS` list) survive outside those branches.
- `SFC_STORE`: which store this build ships to: `'none'` (run from the repo) | `'steam'` | `'itch'` (web + desktop) | `'crazygames'`. `strip-debug.js` writes it when packaging (from `build-web.js <target>`, or env `SFC_STORE` for Electron, default `steam`). Gate platform-specific behaviour on this, not on new booleans.
- `SFC_DEMO`: the itch.io and CrazyGames builds. `config/demo.config.js` locks Area 3+ and ONLINE.
- The itch desktop build excludes `steamworks.js`, so it uses PeerJS like the web build.
- Dev runs can pretend to be a store with `index.html?store=crazygames`.
- **CrazyGames** (`SFC_STORE === 'crazygames'`, Basic launch: only Basic requirements apply):
  - `SFC.Store` (`src/engine/store.js`, `config/store.config.js`) loads the CrazyGames SDK v3 at runtime; boot waits for it (`initTimeout`). It exposes `locale()` and `gameplay(on)` (start/stop on match begin, single-player pause/resume, back to menu; ranked pause stays "playing").
  - Language: a saved choice wins; otherwise a store locale that maps to a pack is used without the popup (not saved). No locale, or no matching pack, shows the language popup.
  - Escape is a restricted key (it exits fullscreen): `controls.restrictedKeys` strips it from every binding, and `Input.key(action, 'Esc')` falls back to the action's remaining key (back → Backspace, pause → P).
  - Store links only on the main menu or at the end of the demo: PRIVATE MATCH shows a "full game" message instead of the WISHLIST screen, and Main Path doesn't pop WISHLIST.
  - `social.enabled` is false: no fake friends, invites, party or chat.
- SETTINGS › PRIVACY NOTICE shows `config/privacy.config.js` (English only, not translated). Update the text when the game starts collecting anything new. Every store.
- Player names go through `Profile.nameAllowed` (`config/namefilter.config.js`), **client side only**: `setName` rejects blocked names, and every name received from others (`sanitizePublic`: room members, match seats; club names in `Session.guestStart`) becomes `nameFilter.fallback`. The dedicated server doesn't load the list, so editing it needs no redeploy. Every store, not just CrazyGames.

**Localization.**
- English source strings are the keys: `SFC.t('...')`, `SFC.tn` for plurals, `SFC.tc('ctx', '...')` for context variants. In UI files the alias is `_t`, never `t`.
- Config text fields are translated in place according to `src/i18n/fields.js`.
- Packs live in `src/i18n/{pt-BR,pt-PT,es,ja}.js`. When adding a player-facing string, add it to every pack, run `i18n-check`, and rebuild the ja font.
- Process, style guide and glossary: `docs/LOCALIZATION.md`, `docs/i18n/`.

## Conventions

- **Controls.** Players can rebind in-match actions (SETTINGS › CONTROLS, `src/ui/controls.js`). The rebindable list, reserved keys (pause / mute) and blocked keys are `controls.remap`; overrides are saved as `Settings.binds` and applied over the config defaults by `Input.applyBinds`, so `SFC_CONFIG.controls.bindings` always holds the live keys. Menus never read match actions: they use their own fixed actions (`confirm`, `back`, `tabPrev` / `tabNext`, `filter`, `equip`…), so rebinding never moves menu navigation. Never write key letters in player-facing text: use `Input.label(action)`, `{action}` tokens (`controls.help`, tutorial lines) or a key-neutral word ("dash", "shoot"). The input layer also supports double-tap bindings (`Tap2.<code>`, unused for now). **Advanced techniques** (user 2026-10-25, for hardcore players, no tutorial, only listed in the controls help `advanced` block): modifiers read while charging in `Human.update`, tuning in `game.technique` — `switch` held + shoot = finesse shot (curl, `Ball.curve`), skill pressed while charging a shot = chip shot (beats a keeper who was off his line when it was struck, `b.fx.chip`), pass pressed while charging a shot / lob = fake shot (`Actions.fakeShot`: nearby AI freeze, AI keeper may dive), skill while charging a through ball = lobbed through ball (`passPlan` mode `lobthrough`). AI never uses them, only reacts; `switch` is the finesse key (remappable) since every match locks the player to one character. PlayStation symbols (✕ △ ○ □) inside any `<kbd>` are swapped for matching SVG icons automatically (`ui/helpers.js`, `.ps-ico`), so keep printing the plain symbol.

- Code comments are written in Vietnamese; keep new comments in Vietnamese to match. Player-facing text is English (the i18n key).
- Popup words over players (SAVE!, POW!, move names…) all go through `Effects.pop(x, y, word, kind, color)`. The kind sets size, outline, shadow and motion so every popup looks consistent: `info` (MISS, HOLD) · `res` (+ULT, counters) · `good` (SAVE!, DODGE!) · `status` (SLIP!, STONE!) · `move` (Core / Ultimate names) · `light` / `heavy` / `huge` (impact words by strength). The colour is the word's own (`'#rrggbb'`; a Core id or school name gives the school colour; omitted = the kind's default) — the user wants each word's colour kept. Sizes, timing and default colours live in `game.fx.popups` (`config/game.config.js`); anchor popups at `p.y - 30`, and popups at one spot stack instead of being deleted.
- Design docs to read before changing these systems: `docs/CORE_DESIGN.md` (Core rules, including "no invisible Cores": every Core needs a visual in `src/render/vfx.js`), `docs/DRILL_DESIGN.md`, `docs/RUN_DESIGN.md`, `docs/TEAMMATE_DESIGN.md`, `docs/SFX.md`, `docs/SAVE.md`.
- To add a Core: add an entry in `config/cores.config.js` (its `desc` is one short line of 7–10 words with no numbers or `{param}` values; the user decided players don't read numbers), and give it exactly one unlock spot: `progression.starterCores` or a Core Road notch (`mainpath.config.js → areas[].road`). The in-match draft picks at random from every Core the player has unlocked (`docs/CORE_ROAD.md`).
- Every non-ult Core belongs to exactly one school (`tags` has one entry; the old two-school bridge Cores were reassigned, 2026-10-13). Only hybrid Ultimates have two tags.
- Ultimate rules (user-approved): Every Ultimate has one use rule (`CoreSystem.ultUse`, shown in the ULT BOOK and the test room; not on the HUD, the user found it ugly): `needsBall` = only while *you* hold the ball (a teammate holding it doesn't count), `noBall` = only while you don't, otherwise anytime (`CoreSystem.ultBlocked`, the X slot dims) — they never teleport-steal the ball. Every Ultimate hit is telegraphed after the cut-in and can be dodged with Z (`Actions.dodged`); close-range ones rush in visibly (`SFC.CoreHelpers.rush`) instead of teleporting. Keep invulnerable states short.
- There are no school resources (Momentum / Rhythm / Rage / Guard) and no synergy bonuses any more (`docs/ULT_RECIPE.md`): Cores trigger on visible states (sprinting long enough = "crackle" `p.surge`, punch combos, the team pass chain `g.passChain`, cooldowns that glow). Ultimates are not picked or unlocked by Area: nobody has one until a recipe is met (`cores.ults.start = null`; Aura Farming and Grandpa's heirloom scene are hidden for now, `SFC_FTUE_HEIRLOOM_ON`), energy charges silently meanwhile, and reaching 3 Cores of one school swaps in that school's Ultimate (`cores.ults.base`), 4 awakens it (level on `p.ultLv`; user rule 2026-10-25: no ★★ shown, the awakened form has its own name + desc in `list[id].awaken` and exactly one new visible mechanic switched on by params that only exist in `list[id].evolve[0]`, plus an AWAKENED cut-in, a glowing form and its own preview `SCENES['<id>:2']`; read through `CoreSystem.ultName / ultDesc / awaken`, see `docs/ULT_AWAKEN.md`), and 2 + 2 of two schools grants a hybrid Ultimate (`cores.ults.hybrids`: all 28 pairs of the 8 schools are covered, Chaos included, behaviours in `src/systems/cores-hybrid.js` and `cores-ult2.js`). A match has 4 Core picks including the pre-kickoff one (`game.match.maxUpgrades`). Every Ultimate stays hidden in the ULT BOOK (`Profile.data.ultBook`; drawn as an 8×8 school-pair table: diagonal = base Ultimate, below it = the hybrid of row + column, last column = awakened form, crown icon) until the player reaches its recipe; opponents' Ultimates still show their names in the cut-in. If it needs custom behaviour, add a `Behaviors` entry in `src/systems/cores.js`, `cores-new.js`, `cores-hybrid.js` or `cores-ult2.js` (the hook list is at the top of each file), plus a preview scene in `src/ui/corepreview.js` (`SCENES`) and its own sounds (`g.sfx('ult', '<id>.<event>')`, recipes in `src/engine/ultsfx.js`, listed in `docs/SFX.md`; don't reuse the generic whoosh / hit / zap as an Ultimate's signature). Every Ultimate uses its own core mechanic (no second "rush at one target" or "line dash"; see the check table in `docs/ULT_REDESIGN.md`). Replacing an Ultimate id: add old → new to `cores.ults.renamed` so ULT BOOK entries carry over. Other Ultimate hooks: `noBall` (blocked while you hold the ball, e.g. Iron Hammer), `recast` (extra uses by pressing X again, e.g. Earth Spike ×3), and shared statuses in `cores-ult2.js` `Stat` (slip, stone, hypno, tiny, chicken, panic; plus `Player.puppet` and `noActT` to block actions) for new designs. A prop can draw a character in place of the player sprite (`PROP_HIDE` / `VFX.hides` in `src/render/vfx.js`: King Kong, boulder rider, chicken).
